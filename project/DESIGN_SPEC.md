# Handoff: 1С Lab — «ИИ под проверкой»

## Overview
Интерактивный электронный образовательный ресурс (ЭОР) для СПО: специальность **09.02.11 «Разработка и управление программным обеспечением»**, дисциплина **ДПБ 1, ОП.13 «Автоматизация бизнес-процессов»**. Сквозной модуль по применению технологий ИИ.

Педагогическая идея: студент не учится «пользоваться ИИ», а учится **проверять результат ИИ** в задачах 1С — схему бизнес-процесса, расчёт окупаемости, запрос на языке запросов 1С, постановку задачи на доработку.

Ресурс односtраничный, работает полностью в браузере: **никаких обращений к ИИ-сервисам и никакого бэкенда**. Весь «ИИ-контент» подготовлен заранее, прогресс хранится в `localStorage`.

## About the Design Files
Файлы в этом пакете — **дизайн-референс, сделанный в HTML**: прототип, показывающий задуманный вид и поведение. Это **не продакшн-код для копирования**.

Задача разработчика — **воспроизвести эти экраны в существующем окружении целевого проекта** (React, Vue, Angular, Blazor, шаблоны Django/ASP.NET, LMS-плагин и т. п.), используя принятые в нём библиотеки и паттерны. Если окружения ещё нет — выбрать подходящий стек и реализовать там.

`1C Lab.dc.html` открывается двойным кликом в браузере (рядом должны лежать `support.js` и `logo-mgpk.png`) — это рабочий прототип со всей логикой проверок.

## Fidelity
**High-fidelity.** Финальные цвета, типографика, отступы, состояния и вся проверяющая логика уже реализованы и проверены. UI следует воспроизводить попиксельно, но средствами дизайн-системы целевого проекта. Все значения — ниже в разделе Design Tokens.

## Interactions & Behavior
- **Навигация:** табы переключают экран без перезагрузки; кнопки «Дальше / Назад» внизу каждого шага и плитки на главной ведут на тот же набор состояний. Роутинг в целевом приложении — на усмотрение разработчика (`/step-1`, `/step-2`, … предпочтительнее).
- **Зачёт заданий (6 штук, счётчик «Выполнено N из 6»):** `quiz` — 3/3 верных ответа; `bugs` — найдены все 5 зон; `roi` — `payback ≤ 12`; `code` — все 4 проверки запроса пройдены; `prompt` — выбраны все 6 обязательных требований и не выбран `trendy`; `checklist` — отмечено ≥8 пунктов. Зачёт идемпотентен: повторно тост не показывается. В прототипе аудит выполняется после каждого обновления состояния — в продакшене лучше вызывать проверку в обработчиках соответствующих действий.
- **Тема:** переключатель «Тёмная/Светлая» ставит `data-theme` на корневой контейнер; переходы `background/color .25s ease`. Внутренние «макеты» (схема процесса, колонки «до/после») используют отдельные токены `--mock-*`, чтобы не наследовать тему страницы вслепую.
- **Масштаб интерфейса:** три уровня — `zoom: 1 / 1.15 / 1.3` на корневом контейнере. В продакшене корректнее задавать `font-size` корня и вести вёрстку в `rem`.
- **Анимации:** `lab-breathe` 3.2s (пульсация ненайденных зон, `opacity .4 → 1`), `lab-sweep` 6s linear (полоса-«свип»), `lab-caret` 1s step-end (каретка), `lab-pop` .18–.22s ease-out (появление сообщения и тоста). Все декоративные — при `prefers-reduced-motion` их следует отключить (в прототипе не реализовано).
- **Адаптивность:** все сетки на `repeat(auto-fit, minmax(…, 1fr))`, заголовки на `clamp()`, у навигации и метрик `white-space: nowrap`. Минимальная ширина области нажатия — 44px везде.
- **Валидация:** числовые поля 2.2 принимают пустую строку (тогда расчёт даёт «—»); отрицательные и нулевые значения не ломают расчёт. Текстовые поля не валидируются.

## State Management
Всё локально, без сервера.

```
tab            'map' | 'l1' | 'l2' | 'l3'
done           { [taskId]: true }            // сохраняется
openCard       number | null                 // раскрытая карточка шага 1
picks          { [questionIndex]: optionIndex }
found          { [bugId]: true }
msg, msgOk     строка + флаг «попадание/промах»
hintOn         boolean                       // подсказка в 2.1
roi            { docs, before, after, rate, cost }
code           string                        // текст запроса студента
codeResults    [{ label, ok }]
chosen         { [chipId]: true }            // сохраняется
checked        { [index]: true }             // сохраняется (чек-лист)
reflection     string                        // сохраняется
fs             1 | 2 | 3                     // сохраняется (масштаб)
theme          'dark' | 'light'              // сохраняется
typed, toast   вспомогательные (анимация печати, тост)
```

Персистентность: один ключ `localStorage` — `onecLab.progress.v1`, поля `done, reflection, checked, chosen, fs, theme`. Ответы на вопросы, найденные зоны, цифры расчёта и текст запроса **не** сохраняются — это осознанно, задания перепроходятся с нуля. Никаких fetch-запросов нет.
